# 运营候选与本地每日推荐

适用于包含 selection_automation.operations 和 operator_daily.py 的运营工作台分支，不据此覆盖其他聊天的采集恢复代码。

- 新任务在采集前设置同款数严格少于N；恰好N个排除。旧任务未设置same_operator时保持原来的lte边界。
- 同一运营可订阅多个已准备品类，推送时刻保持一致；每天按北京时间从这些品类中选至多一个合格候选。推荐结果和近期去重记录落盘，无合格证据时记录无推荐，不凑数。
- 同款数只采用已验证第三层结论，核对确认商品ID明细。待分析、待复核、零样本、当前快照缺失不作为零竞争。范围限定当前采样与候选规则，不能称TEMU全站总数。
- 最低价/最高价来自页面明确区间或实际可售规格。单项标价只保留已见价格，规格上下限未知；规格子集注明子集。划线原价与促销价不组成规格范围；非美元价格不标成USD。
- 评分、销量和评论数分开。1K+等保留显示下限和周期口径，BSR不换算销量。Amazon明确bought in past month才写页面月销量文本。
- 新品需要真实上架时间及来源，首次看见或最近上架排序不能替代日期。差评仅保存实际1至2星原文和具体来源，不根据标题或模型常识编造差评点。
- 本地日报不发送外部消息。唯一进程锁和原子记录防止重复推送，已启用订阅随程序启动恢复。外部推送需明确渠道与收件人。
- 每日新采集可单独开关，默认提前120分钟排队。每品类每天至多登记一个新任务，跨运营共用此任务；新任务沿用本品类已审核规则，重新采集Amazon并创建新环境。不抢占现有监督器，不自动重复启动结果不明或失败的任务；过了推荐时刻才空闲则当天跳过。验证码、登录墙或403/429保留等待，不换会话绕过。
- 启用每日新采集的订阅只用当天任务证据推荐；当天排队或未启动不能使用历史模板结果冒充新品。第三层付费视觉仍不自动启动，待核验或缺来源的商品不入选。定时器/队列测试通过不代表站点门禁或全流程已经跑通。
- 同品类可沿用本机已运行的有效规则，但精确匹配品类后仍需重新读取真实榜单，核对具体标题与排名，并重新采集榜单标题和来源关键词。新品类不能使用其他品类模板代替。品类模型HTTP402与浏览器加载失败分开记录，已存规则复用不再请求模型解释。
- 原始Amazon/TEMU导出末尾附加规格上下限、区间口径、评分、销量口径、上架来源和真实差评字段，保持原有主要列位和图片链接。共享数据的多个目录使用相对证据路径与代码内容签名，避免交替发布旧报告。
- 维护重启通过task-root显式指认旧目录监督器，仅当双方共享同一runtime且PID、创建时间、命令和任务均匹配时保留，不停止未知进程。
