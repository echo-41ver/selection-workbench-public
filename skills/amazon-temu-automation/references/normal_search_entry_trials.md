# 正常搜索入口与独立实测

采集器的 `--entry-mode` 必须真实执行对应入口：`empty_search` 使用空搜索页输入，`home_search` 使用首页可见搜索框输入，`direct_search` 使用普通关键词搜索链接。生产默认改为 `home_search`，新建及替换环境的初始 `tabs` 直接打开 `https://www.temu.com/`，在首页输入关键词并点击搜索图标。已经在目标关键词页时不重复跳转；切换关键词时复用当前结果页搜索框。入口参数不能只是被读取却全部进入同一页。

入口实测使用 `scripts/run_entry_trials.py`：新建独立 AdsPower profile、新代理 session、独立代理和 WebDriver 端口，每个方案独立保存 `case.json`、页面历史、原始商品、排序状态和结束原因。不修改正式任务 manifest，不向正式数据合并实验商品。

“启动即关键词页”必须把关键词链接写入新 profile 的初始 `tabs`，不能用空白页后的导航冒充。代理活动许可在启动浏览器前建立。首页、空搜索页和关键词页的正常顺序组合与实际搜索提交方式分别记录；页面出现验证码、登录墙或拒绝访问时结束该实验，不自动处理验证。

只有排序经 UI 确认、该关键词达到配置数量或真实结束规则、且没有人工介入，才记录完整关键词成功。一次成功不等于永久无门禁；候选入口需用新环境重复验证，并验证后续排序、采集与分析导出。

实验清理先释放自己绑定的 WebDriver，再让 AdsPower 停止自己创建的 profile；确认已关闭后才能删除。清理失败保留身份记录，暂停创建下一批环境。进程操作同时核对 PID、创建时间和命令，不能影响正式采集器。

验收看 `report.md` 与各案例实际证据；`COLLECTOR_EXIT` 不能当作成功，必须展示实际终止状态。报告区分门禁失败、基础设施失败、超时和完整关键词成功。

生产首页方案的图片拦截在浏览器绑定后启用，首页首屏加载可能先于拦截器；关键词提交前仍必须通过 IMAGE_BLOCK_GATE_PASSED。验证码图片保留既有放行规则。当前搜索页的断点和换词仍使用现有搜索框，不强制跳回首页。普通入口只作为实测候选，不能承诺永久无门禁。
