# 同事版选品结果与第三层配置

默认交付 `<品类>_选品结果.xlsx`。首页设置 N 后，严格筛选当前采样已确认、按 goods_id 去重的同款数小于 N 的 Amazon；等于 N 的商品不入选。保留三张精简表：选品结论、同款商品明细、商品完整字段。只写入入选 Amazon 和对应确认同款，不导出第一二三层全部笛卡尔积；完整检查点仍供增量分析使用。

尚未完成候选核验的入选商品必须标明待分析、待补证数量，并写“待完成同款核验”，不得给出最终低竞争推荐。零同款仅表示当前采样未发现同款。评分、评论数、销量原文与口径、当前价格、规格最低/最高价、价格带来源、规格、变体、品牌卖家和实际已采集字段随记录交付；未取得的字段不猜测。单个当前价不冒充所有规格价格带；部分 SKU 有价格时，只能标为已采集子集。页面价差不等于利润。

第三层由网页单独启动，可选 Liquid D1 原生决策接口、Responses/Chat Completions 多模态 API、本地模型服务或本机 Agent 并行看图。API 地址包含协议、主机、可选端口和接口路径；模型 ID、并发数可编辑，决策概率门槛可配置。Key 只传给同次明确选定的服务地址，不写入品类配置、源码、Excel 或发布包。

Liquid 看图使用 `d1`，不使用仅支持文字的 `d1:free`。原生决策每次一个商品对、两张原图，输出同款/不同款/证据不足概率；不生成解释性事实或伪造模块评分。中间概率与证据不足保留为待补证。概率门槛是工程分流参数，不能冒充已校准识别准确率。

本地模型可连接本机 D1 `/v1/systemone`，或其他已启动且支持图片的 Responses/Chat Completions 服务。本机 Agent 使用已登录的 Codex CLI，按设置并发派单，严格校验视觉事实并写入原有断点。停止第三层只停止它自己的工作，不停止采集。

变更采集、模型、图片或身份规则时保持原任务断点；服务方案与接口参与视觉版本隔离，旧方案结果不混入新方案。代码发布和网页重载不得重启正在运行的采集监督器或浏览器。独立网页维护只有通过运行任务身份检查后才能使用 `restart_web.py --keep-task`。

协议来源：https://docs.liquid.ai/lfm/models/d1 、https://api-docs.deepseek.com/guides/vision/ 。协议适配离线通过不代表已使用用户 Key 完成真实服务验收。

DaiTu GPT 沿用新建任务页的原生 Responses 分流，未填写路径的服务地址自动补 `/v1`，以完成事件作为成功依据；保留请求编号、用量和低推理强度。中断或输出截断后暂停，不自动重复付费。相同任务、相同服务可沿用服务内存中的 Key；服务重启后需重新填写。前端只展示总进度和业务结论，不展示 API/Agent 内部拆分和采集器实现说明。
