# 同事版选品结果与第三层配置

默认交付 `<品类>_选品结果.xlsx`。首页设置 N 后，严格筛选当前采样已确认、按 goods_id 去重的同款与类似款合计小于 N 的 Amazon；等于 N 的商品不入选。保留三张精简表：选品结论、同款商品明细、商品完整字段。选品结论仅写入入选 Amazon；同款商品明细写入全部最终同款与类似款，不导出第一二三层全部笛卡尔积；完整检查点仍供增量分析使用。

尚未完成候选核验的入选商品必须标明未分析、无法判断数量，并写“待完成同款核验”，不得给出最终低竞争推荐。零同款仅表示当前采样未发现同款。评分、评论数、销量原文与口径、当前价格、规格最低/最高价、价格带来源、规格、变体、品牌卖家和实际已采集字段随记录交付；未取得的字段不猜测。单个当前价不冒充所有规格价格带；部分 SKU 有价格时，只能标为已采集子集。页面价差不等于利润。

第三层由网页单独启动，可选 Liquid D1 原生决策接口、Responses/Chat Completions 多模态 API、本地模型服务或本机 Agent 并行看图。API 地址包含协议、主机、可选端口和接口路径；模型 ID、并发数可编辑，决策概率门槛可配置。Key 只传给明确选定的服务地址，不写入品类配置、源码、Excel 或公开包。D1 Key 可用 Windows 当前用户加密保存；含真实配置的完整内部包仅在私密仓库发布，新机导入后重新加密。保存配置不会启动付费分析。

Liquid 看图使用 `d1`，不使用仅支持文字的 `d1:free`。原生决策每次一个商品对、两张原图，输出同款/类似款/不同款概率；不生成解释性事实或伪造模块评分。中间概率与证据不足显示为无法判断。概率门槛是工程分流参数，不能冒充已校准识别准确率。

本地模型可连接本机 D1 `/v1/systemone`，或其他已启动且支持图片的 Responses/Chat Completions 服务。本机 Agent 自动发现 Codex、Claude、Gemini、OpenCode、WorkBuddy、AccioWork 和豆包，并分别读取当前账号的原生模型列表。网页先选择“Agent 分析”，再从一个下拉框选择 Agent，然后显示该 Agent 的模型下拉框。默认只使用明确选择的一个 Agent；只有展开“多 Agent 同时分析”并主动添加，才会让多个 Agent 分担不同商品，每对商品只分配一次。实际调用只提交已选择的 Agent 和对应模型；未选择时禁止提交，不能将空列表解释成全部 Agent。换机后重新发现，连接与看图证明按模型分别记录。WorkBuddy 使用内置 CLI 的独立后台会话，不在桌面任务列表新增任务。AccioWork 使用本机网关；豆包使用用户已授权的 127.0.0.1 CDP。严格校验原图绑定与视觉事实，写入原有断点。停止第三层只停止它自己的工作，不停止采集。

变更采集、模型、图片或身份规则时保持原任务断点；服务方案与接口参与视觉版本记录；显式中途切换在原图与规则不变时可沿用旧方案已完成事实，并保留实际来源模型。代码发布和网页重载不得重启正在运行的采集监督器或浏览器。独立网页维护只有通过运行任务身份检查后才能使用 `restart_web.py --keep-task`。

协议来源：https://docs.liquid.ai/lfm/models/d1 、https://api-docs.deepseek.com/guides/vision/ 。协议适配离线通过不代表已使用用户 Key 完成真实服务验收。

DaiTu GPT 沿用新建任务页的原生 Responses 分流，未填写路径的服务地址自动补 `/v1`，以完成事件作为成功依据；保留请求编号、用量和低推理强度。中断或输出截断后暂停，不自动重复付费。相同任务、相同服务可沿用服务内存中的 Key；已加密保存且绑定当前端点的 D1 Key 可在服务重启后恢复；其他仅在内存中的临时 Key 重启后需重新填写。前端只展示总进度和业务结论，不展示 API/Agent 内部拆分和采集器实现说明。

2026-10-14 用户修订：不使用 D1 免费文字层。采集与本地第一、二层继续自动运行，D1 看图使用一条 Choice 问题，在同款、相似款、不同款中三选一；低概率保留待补证，概率不是已验证准确率。N 按最终同款与类似款的商品 ID 去重合计严格筛选，等于 N 排除；未完成分析不作零竞争结论。

精简 Excel 的选品结论仅保留最终同款与类似款合计严格小于 N 的 Amazon，每个 Amazon 一行，展示图片、五项数量及全部已采集 Amazon 参数。同款商品明细保留全部最终同款和类似款商品对，不受 N 过滤；双边图片嵌入并链接原图，双边销量、价格、评分、规格等参数可见，模型名称从实际 Agent 模型目录解析，完整原始字段另存。

采集完成与分析、市场数据及 Excel 发布分开判定。TEMU 所有计划关键词和排序轮次结束、各采集路完成，且 Amazon 榜单及详情满足目标后，网页显示“全部采集已完成”。仅数量达到目标但最后一轮未结束时进度最高 99.9%，不能用百分比四舍五入冒充完成；分析监督进程存活不代表采集仍在进行。

网页以全部 Amazon 商品的实时表格替代选品结论卡片：ASIN、标题、实际图片、同款、类似款、不同款、无法判断、未分析，以及价格、销量、评分和其他已采集参数。无法判断表示已有结果但证据不足，未分析包含尚未处理及前两层筛除未做看图的商品；不能将相似度筛除直接称为不同款。明确双边核心身份冲突判不同款，模型字段自相矛盾须补跑或保留无法判断。整体证据可见度必须由模型按原图填写，禁止照抄零值占位；矛盾输出作为失败按上限补跑，不能伪造置信度。

第三层 API、本地模型及本机 Agent 按相同 Amazon 原图和事实版本分组，每组最多十二个 TEMU；Amazon 原图只传一次，TEMU 使用带 Cxx 编号的清晰拼图并保留原图映射。按整组分配，跨旧分片合并候选并预取足够完整组；只有真正尾组可不足十二。D1 按用户确定的省费用方案，每个物理请求仅比较一对、两张图、一条 Choice 问题，多路并发并复用图片编码和 HTTP 连接。其他方式使用一对多、多组并发。并发按实际成功吞吐量调整，失败或收益不再增长时回退。

第三层支持全局暂停与继续、单 Agent 暂停与继续，以及保存断点后更换方式、Agent 或模型。暂停只停止派发新组，已发送结果继续保存；切换方案先收回当前请求再自动应用新方案。只有显式方案切换可沿用旧方案的已完成事实，须同时匹配原图、记录和判断规则，并保留实际分析模型来源。费用或发送状态不明的任务恢复原会话观察，不盲目重复提交。豆包用桌面输入页串行提交附件，随后独立会话并行观察，不以多个任务争用同一输入框。

本机 Agent 之间或模型之间中途切换时，新组立即使用新选择，已发送组沿用原 Agent 和模型收回结果；API 或跨方案切换则先保存当前请求再接续。旧模型未完成的商品按兼容版本键继续预留，不能换模型后重复分配。豆包多候选复用已验证的共享基准短输出协议，只要求 Cxx 编号和完整短事实；本机按原清单补回商品 ID、版本及实际模型，并使用同一严格解码器检查，不补造商品事实。

豆包恢复观察页使用原生 doubao 地址，不能把内部 chrome 地址直接用于新建观察页。恢复观察不消耗重新分析次数；收到完整响应时同步原会话的接收状态，随后仍独立校验事实。不在发送结果不明时重复提交模型分析。

本机 Agent 明确结束回复后，读取失败属于输出失败，不能无限等待原会话。保留原始回复；仅兼容不改变事实的数字类型和末尾闭合括号，旧协议版本串按完整且唯一的商品 ID 集合绑定回本地原图清单。恢复时从原任务继承输出协议；已收到回复的原任务不再预留观察位置。各候选独立通过严格校验后立即入库，仅补跑缺失或无效候选；出现未知或重复商品身份时整组拒收。

Windows 结果文件短暂占用先有限退避写入；仍失败则原地重试入库，不能再次调用模型或消耗分析重试次数。本地观察连接中断不作为模型分析失败参与并发降速。豆包观察进程退出时关闭自己创建的观察页，包括观察页创建阶段的连接超时；保留远程对话及发送凭据，恢复时重新观察，避免失效页面积累。
2026-10-16 第三层阻塞处理：豆包出现人工验证码时，在模型菜单、输入和观察阶段明确报出人工验证并暂停该 Agent，保留断点；禁止自动解题、绕过或重发发送状态不明的请求。确定未发送的失败不消耗模型重试次数。发送未绑定会话的任务隔离且不占观察槽；已有会话连续三次观察失败后隔离该组，其他组可继续。单行 JSON 损坏不能阻止其他合法且身份绑定的候选独立入库，原文件保留，不补造事实。API 的确定性请求错误停止该通道，并显示经过密钥及图片脱敏的服务错误；变更端点、模型或协议后重新检查适配。DeepSeek Chat 使用 json_object 并附带 Schema，Responses 保留 json_schema；结果仍经本地严格验证。本地服务无有效响应时限时停止，按无远程费用处理；不得将小量协议测试当成准确率或长期速度验收。
