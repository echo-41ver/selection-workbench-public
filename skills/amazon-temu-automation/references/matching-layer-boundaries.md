# 三层同款分析边界修复

分析与采集保持分离。以下规则用于现有三层分析器，不改变采集脚本、品类阈值、模块权重、模型或付费授权。

## 第一层

声明式属性只有双边唯一明确且不同、属性设为硬冲突且没有歧义时才排除。有缺失、多值或歧义时记为 TEXT_INSUFFICIENT，继续第二层；不得把未排除表述为属性已经一致。不存在缺失或歧义且无冲突才记 TEXT_PASS。

通用解析器识别短语前后的否定、排除和外观措辞（如not made of cotton、cotton-free、不是纯棉、仿纯棉、cotton-like），不把它们当成正向属性证据。语境不确定时继续图片核验；明确双边身份冲突仍排除。stage3.variant_fields明确允许且不是整个模块的普通变体属性不能按文字硬冲突误排。

现有浴巾v5与浴帘v2适配器共用同一语境检查，保留各自件数、子类型等身份规则；不会只修新品类的声明式路径。语境引擎与适配器内容一起进入本地处理修订键，正常接收数据时重新处理旧文字决定，只读导出不改数据库。

## 第二层

使用 float64 归一化向量，批量计算余弦相似度乘100，并裁剪数值误差到理论范围。零向量、非有限向量、双边维度不一致进入有界失败重试，分数保持未知，不进入候选或低分排除。

本地ResNet50仍使用同一套ImageNet1K_V2权重，每件商品增加三种视图：原有中心视图、留白保留完整主体的视图、仅在图像边界足够均匀时提取的主体视图。场景图不能可靠提取时保留整图，不声称已完成通用主体分割。每个视图为2048维，按视图分别归一化，取九个视图配对中的最大余弦分数；保留原中心/中心路径，因此在相同图片和阈值下不会因新视图降低原有召回。多视图用于候选召回，不能证明同款；候选可能增加，第三层仍负责款式排除。编码按32张视图分块限制内存，图片与向量按新revision缓存。

入围判断使用四舍五入前的分数；存储显示值保留四位小数。因此接近门槛的商品对可能显示50.0000但实际略低于50，状态仍为第二层未入围，以状态为准。第二层分数不参与最终综合分，未校准品类的低分不能替代最终不同款结论。

本地处理契约包含 cosine_policy=float64-normalized-unrounded-threshold-v2。旧数据库下次由正常分析入口接收或处理时重排第一二层，保留图片、向量缓存及商品对版本；只读查询和导出不会触发重算。

## 第三层

即使供应商没有严格遵守 JSON Schema，本地也检查候选数、候选ID唯一性、完整模块集合、字段类型、允许的关系与硬冲突代码。拒绝额外模型评分字段及格式错误的响应；这些不能记为成功结果。

置信度必须是有限的0到1数值，布尔值、字符串、null、NaN和Infinity均拒绝。双边证据须为非空字符串。声明一致或允许变体却同时给出硬冲突代码时，在没有其他有效硬冲突的情况下输出待复核，并保留 contradictory_modules，不得自动确认同款。双边有效硬冲突仍优先排除。

通用视觉协议升级为 whole-product-identity-v6-reviewed-variant-boundaries，所有现有及新生成品类共用。模型先判断整体基础款，返回identity.verdict、design_comparison、matches、differences、uncertainties、reason；每条细节分别描述Amazon与TEMU的可见事实。design_comparison必须实际比较本体轮廓、部件造型及排列、边缘或图案设计，而不是仅列同类共有部件；明确双边款式差异直接排除，SIMILAR、UNKNOWN、缺失或笼统证据不能确认。共同细节按实际可见内容填写，不设两条细节的硬门槛、不要求简单商品凑条数；只有笼统同品类、同结构或与基准一致不能确认。额外字段和非法结构在本地拒绝。

两侧对应部位均完整清晰可见时，一侧有关键特征而另一侧确实没有，记明确身份差异。只有真实遮挡、折叠、裁切或无法辨认才记图片未知；不能因为模型少写一项细节，就把清晰图片说成证据不足。

uncertainties保留模型描述的可见性限制，但不能仅因列表非空就否定整体同款。非关键角落或营销标签遮挡在主体身份和关键模块已明确一致时不阻断确认；整体UNKNOWN、关键模块UNKNOWN及未解释身份差异仍阻断。不能把“任意局部没看见”当作“无法识别款式”。

模块分数只供辅助查看，不再决定最终状态。可用identity_required_modules明确列出可见的关键身份模块，未提供时兼容confirmation_minimums中的模块键；没有关键项时检查全部模块。未知的关键身份仍阻断；没有露出的非关键电池仓或后接口不能由辅助权重自动升级为身份要求。关键模块须SAME；只有module_variant_fields明确绑定且有双边允许变体事实的V可兼容，SIMILAR及未解释V待复核。模块明确DIFFERENT配合整体不同判断即可排除，不依赖模型一定正确填写硬冲突代码。整体一致与模块不同矛盾时待复核。明确双边身份差异直接排除，无论辅助总分多高。

允许变体仅来自variant_fields中的具体名称，自动过滤整个模块键；本体图案、边饰布局、结构、主体类型、套装构成差异不能笼统写成变体。浴巾可按人工确认标准明确允许decorative_pattern：主体织法、构造与阴刻/装饰带数量位置及布局必须对应；花纹和颜色可变。此例外不适用于浴帘整幅印花，也不允许多条独立宽带合并成一条。套装总件数相同不代表构成相同。普通颜色变化必须建立在本体设计一致的基础上。

每条差异的field是中文显示名称；variant_field是Schema枚举约束的配置标识。VARIANT使用允许的标识，IDENTITY及UNRESOLVED使用NONE。中文吊牌/包装等名称不与英文配置标识直接比较；无法识别的变体名称进入待复核，不凭名称不匹配判不同款。此规则适用于任意品类，不是浴帘或浴巾专用映射。

供应商仅包裹一个完整JSON代码块时，可去掉该外包装再执行同一严格解码。也可从纯文字前言后提取唯一、完整、位于末尾的 candidates JSON；前言含其他JSON、多个对象、包装对象、末尾说明或残缺JSON仍拒绝。不能改写、删除模型事实字段或修补残缺JSON。非VARIANT差异的variant_field必须为NONE。错误格式及非法事实仍记接口失败，按原有界重试处理，不计商品识别成功。

单对输出预算至少16384，按模块数和候选数增加，最高32000；旧品类配置明确写入4096等低预算时也应用16384下限，避免推理占满预算而来不及输出JSON。更高的显式预算仍尊重。推理耗尽输出额度且未返回JSON记请求未完成，保留实际token记录，不能记成商品图片证据不足。原有有界重试、付费开关和请求上限保持有效。

移除旧浴帘自动抬高零置信度、调换双边证据和用营销字样改写视觉事实的纠偏。UNKNOWN不填充45%权重；辅助总分有未知即为空。导出层禁止用高向量分改写第三层判断，所有品类的Excel与商业汇总复用同一最终判定，并显示整体证据。

通用强制身份协议不能被prompt_override整体替换；用户编辑作为品类补充规则保留。视觉缓存版本随提示词和Schema升级自动失效；历史导入必须匹配当前视觉版本且有整体核验，不允许仅凭图片相同把旧事实重标为新版成功。旧成功记录保留，但不进入新版确认。

浴巾confirmation_minimums的known_modules与evidence_quality历史元数据兼容并检查合法值；拼错的模块名仍拒绝。真实模型实测与离线流程测试分别记录；少量已知错例通过不代表全品类总体准确率。

## 验证与运行

以后第二部分每次改动均须同步运行代码、网页说明与实际规则展示，完成Git提交并用scripts/build_release.ps1（或提交钩子）更新部署包。检查dist/最新部署包.json指向当前提交；不能只修改本机脚本而留下旧网页或旧分发包。网页不得继续把模块分数说成最终同款标准。

离线边界测试：`python -m pytest tests/test_whole_product_identity.py tests/test_matching_layer_boundaries.py -q`。集成验证覆盖增量数据库、候选队列、视觉缓存身份、浴帘/浴巾/电钻、新品类及Excel导出。案例输入为结构化模拟事实，测试流程判定，不替代真实模型识别评测。

三项准确性目标回归入口为tests/test_accuracy_objectives.py：文字否定/外观/多值与允许变体不误排，明确文字冲突仍排除；原候选不丢失、完整长条商品及多视图召回进入真实候选队列，非法向量不作数值判断；多个品类整体SAME但款式SIMILAR或DIFFERENT不能误确认。

修改代码不会自动启动采集或付费分析。正在运行的Python进程需在其正常停止和续跑后载入新版；保持原任务与断点，不删除数据库或成功视觉事实。模型提供整体视觉判断和事实，本地规则检查证据后生成最终结论。

## 网页采集到分析的自动衔接

采集监控按采集器当前快照刷新每路数量、排序目标、轮次与观测时间；总采集进度独立于分析汇总刷新。独立Codex看图进度累计同一任务的有效批次，尚未分派且全部清单为空的初始化批次不参与完成判定；非空批次错误仍须保留。实时批次进度与带核验时间的全量有效结果分类分别显示，不能混用两者数量。已明确发布的综合Excel允许直接打开，不要求创建付费授权标记；查看文件不启动分析。

网页运行按钮提交当前人工确认的第一层规则、第二层阈值、第三层规则与模块、商业条件和采集路数；默认execution_mode=full，不能固定提交collection。启动监督器时不附带--paid，不创建paid_enabled.json。Amazon与TEMU快照持续自动进入本地第一、二层及候选队列；第三层必须等用户点击网页按钮才能启动。明确指定只采集的CLI/API兼容路径保留。

旧网页已经启动的只采集任务，可在用户要求打通流程时用scripts/attach_local_analysis.py attach --category runs/<key>/category.json接入；仅改变该任务执行模式，校验并保留原规则、采集数量、关键词、数据及原配置备份。桥接进程接管本地分析，第三层只接受同任务web-console授权标记；不重启采集浏览器。停止时关闭自己启动的分析子进程；以后正常续跑full监督器先交接桥接进程，避免重复分析。未运行的历史数据不擅自启动整轮采集或批量付费分析。

跨品类抽样先冻结随机种子、商品对和原图，再记录人工参考判断及置信水平，之后进行独立视觉实测。分别报告明确正确、待复核、接口失败和误判同款；全是负例的小样本不能作为全品类准确率或同款召回率。

## 新品类统一标准生成

新品类以 category-identity-policy-v2-effects 定义唯一 identity_policy，再编译文字属性排除、具体允许变体、关键身份要求和视觉说明。每个特征须说明 region、effects、role、evidence、scope、rule、modules、required_visual；variant 另须用 preserves 引用需要保持的可见身份特征。文字属性复用同一特征 ID，不独立维护另一套身份判断。

按变化影响检查结构，不能靠名称黑名单：出售主体的形状、布局、连接、功能、主体织法、透明度不能整项设成允许变体，也不能将可见结构降为仅供说明。允许的表面变化拆成具体部位特征；包装仅指本体之外的包装，不把出售主体或集成部件改名为包装绕过约束。装饰区域内部纹样与区域布局分别定义，不能将所有品类图案统一视为变体或身份。

preserves 只列与该变化有关的最小可见身份条件，不能要求颜色变化额外证明无关的背部接口或挂环。required_visual 选择足以辨认款式的最小常见可见集合；其余身份特征明确不同时仍排除，确实未展示则保留未知，不冒充一致。无法可靠取得的属性只能作为 context；明确文字可证的属性不得凭图片猜测。

已确认边界通过 identity_profiles 的品类资料进入生成、修正与视觉说明，不能用商品对 ID 特判。无对应资料的新品类使用通用契约，不套用浴巾或浴帘例外。违反边界最多修正一次，再失败不创建任务；旧 v1 草稿须重编，不凭名称猜测升级。无 identity_policy 的旧配置保持其原执行契约。

新生成标准要求逐项 feature_comparisons：每个可见身份特征分别返回两边事实与 SAME/DIFFERENT/SIMILAR/UNKNOWN。明确身份部位差异优先排除，确认必需部位缺少有效对应不能由辅助模块分数补齐。变体须有其 preserves 条件的双边一致证据。模型读取图片有误时，格式与逻辑检查不能证明其观察正确，必须用冻结原图和独立参考实测。

reference_examples 为可选的人工确认图片资料，默认不启用。仅使用部署资产中的原图并验证 SHA256；参考任一图片与待分析任一图片相同，则排除整条参考，避免直接泄漏答案。已知错例通过不代表示例增强可默认上线；保留失败、不改标签、不用重复请求挑选成功结果。

## 正常会话连接与列表广告观测

本地连接以指定配置的唯一浏览器根进程、MarionetteActivePort 和驱动进程归属为依据，不要求窗口抢到前台，不注入桌面输入。端口被非所属进程占用仍拒绝连接。此修复只连接正常现有会话，不解除登录、验证码或网站拒绝访问；真实恢复须在允许恢复批次后另行验收。

列表卡片仅在全文未截断、完整处于视口内且实际扫描卡片文字和可访问标签时记录 is_sponsored 布尔观测，并保留 sponsorship_observation=VISIBLE_COMPLETE_CARD_LABEL_SCAN_V1。隐藏、截断、视口外、部分显示卡片及旧快照缺证据时保持未知，不根据没有字段推定非广告。未展示销量保持未知，响应 JSON 不能补造广告或销量观测。

非广告负观测还要求页面 complete、无加载占位，并在至少两秒后再次观测到相同完整文字及可访问标签；第一次或延迟标签改变时保留未知。明确广告标签可立即记 true。每次有效观测保留 sponsorship_observed_at，缺观测的已收商品后续可见时再次检查，不改旧快照。

既有视觉事实可用 scripts/audit_saved_vision.py <保存响应目录> --output <审计JSON> 只读重放。先核验相邻冻结品类配置SHA256，再评分，评分后才对照参考标签；拒绝缺失事实/不匹配配置，空输入不得报告成功。报告不提升生产缓存、不覆盖原响应、不产生API请求。重复商品对的不同尝试按历史尝试报告，不能用于总体准确率。

综合Excel的可见视觉关系与品类部位名称使用中文，待复核依据列出实际未证实的必要部位或未解释差异，不将非必需未展示部位自动视为阻断。网页结果页按需读取最近已发布综合Excel的有限待核验样例，注明来源文件/时间与抽样范围；展开不启动分析、付费或重建Excel，任务切换与快照更新不得混用来源。此显示改进不改变模型原始事实、最终评分或缓存身份。

综合Excel导出允许没有商业报告或单品match；此类商品不计商业SAMPLE_PASS，不补造商业事实，也不能阻断全量商品对导出。历史仅采集配置的本地综合导出保持兼容，第三层付费授权仍由原入口独立检查。

### 部分结果与崩溃边界

第三层请求前持久记录request_intents，结果落盘后才结算；存在未结算或坏记录时仅暂停付费重发，先核对供应商用量，不自动删账本或当零费用。已保存完整结果仍可发布，未完成日志末行只在展示中有限容忍并提示未知，冻结输入/中间坏行保持严格。明确双侧相反来源只待复核、保留原文，不自动交换；一般引用另一图不能据此认定来源颠倒。
