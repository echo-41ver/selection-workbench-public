# 三层 Excel 发布状态

`publish_all.py` 和 `watch_stage3_excel.py` 共用任务的 `publish.lock`。两者成功交付三层查看副本或快照时，必须更新同一份 `publish_state.json` 的 `stage3_excel`、`stage3_excel_database` 和发布时间；主发布程序不能只更新普通 `analysis` 标记，否则独立观察器会把已经交付的工作簿持续显示为待更新，并再次导出。

输入签名在导出前捕获，交付成功后才保存。导出期间出现新视觉事实或新输入时，当前签名仍应不同于已交付签名，继续下一次发布，不能使用导出后的签名把新增结果错误标记为已交付。

网页按钮能返回 XLSX 与该工作簿已经包含当前全部结果分别验证；HTTP 200 本身不证明最新结果完整。固定查看副本锁定时沿用既有快照交付规则。

冻结判断使用 `selection_automation.publication_revision.database_signature` 在同一 SQLite 读事务内对商品事实、商品对结果、候选、图片状态和错误状态生成签名。最后观察时间、重复接收计数和数据库文件修改时间不作为新事实。只有视觉复核结果变化时复用已冻结的一二层输入；真实数据库结果变化仍重新冻结。记录数据库签名时使用冻结前的签名，不能在长时导出结束后把较新的数据库误标为已经导出。

## Amazon最终结论与低同款专表

通用三层综合工作簿首先提供 Amazon最终结论，按实际导出的最终判断统计每个ASIN的确认同款、待复核及待补证、不同款、未分析或未入围数量。读取本任务采集前 commercial.same_limit 的最多允许同款数，条件为确认同款数不超过上限。待复核或未分析存在时，结论保留待复核，不能写成全部核验通过。

同款不超过N_同款及待复核 专表按当前确认同款数选择Amazon，即使仍有待复核也收录；只写这些Amazon的同款、待复核及待补证商品对，排除不同款、未分析和第二层未入围。不再依赖商业报告 SAMPLE_PASS 才选Amazon，也不把入选Amazon的全部商品对写入专表。主全量表及原有最终判断列保留兼容。


新增的 Amazon最终结论 表直接显示Amazon主图；低同款专表直接显示Amazon和TEMU两侧图片，使用随单元格移动和缩放的锚定缩略图，保持WPS/Excel兼容。优先复用当前候选绑定的本地图片缓存，并按主图URL缓存缩略图；缺图明确标注，不用其它商品图片替代。全量综合结果保持图片链接，避免对几十万行重复嵌图。
