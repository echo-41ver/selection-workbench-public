# 同事的一键部署说明

公司内部使用“内部运行版-含公司完整配置.zip”。解压到固定的短目录，例如 `D:\选品工作台`，双击 `deploy.cmd`。也可以让本机 Agent 执行：“按本说明运行 deploy.cmd，等待部署检查通过并打开工作台，不启动采集或付费分析。”

目标电脑使用 Windows 10/11 x64，预留至少 12 GB 可用空间，并开启该机可用的公司 VPN／代理。安装绝对路径不超过 100 字符，支持中文和空格。不要在 ZIP 内直接运行。缺少 VC++ 运行库时，Windows 可能显示管理员安装确认。

从具有打包应用文件视图的 Agent 宿主启动时，一键入口会检测上下文，并把部署转到当前 Windows 用户的交互桌面任务；普通资源管理器启动沿用正常入口。此处理不更改系统 MSIX、权限或安全设置，也不代替后续真实安装检查。涉及公司配置的导入仍使用同一用户；需要确认的窗口和管理员提示请按实际提示处理。

如果 Windows 阻止后台自动切换浏览器窗口，程序会显示一次“继续显示浏览器”，点击“确定”即可继续。取消或超过一分钟未确认会停止本次检查并保留浏览器；程序不会把未激活的浏览器记为通过，也无需同事执行命令或改系统设置。

完整包随带固定版本 Python 3.12.10 安装器、便携 Node.js 24.19.0、便携 PowerShell 7.6.5、VC++ 安装器、Python 依赖、Playwright 模块和 Chromium、AdsPower 8.7.23 安装器、第二层 ResNet50 模型和 Codex CLI。先核对随包文件的 SHA256，再执行安装器；不要求目标电脑预装 Python、Python Launcher、Node、Git 或 WinGet。AdsPower 的账号授权、Firefox 153 内核准备和实际站点访问需要联网。

完整内部包会自动导入随包的公司配置，在目标电脑按当前 Windows 用户重新加密。AdsPower 使用公司 API Key 启动后台服务；代理和默认分析 API 使用公司配置，无需同事逐一登录这些服务。程序不复制原电脑的账号登录缓存。使用本机 Agent 时，由同事使用该机自己的 Agent 账号；部署期间不会强制弹出 Codex 登录。普通内部基础包和公开包不含公司凭据，不能代替完整公司配置包。

网络继续自动识别当前电脑的 HTTP／SOCKS5 出口和 TUN 路由。完整包不带旧电脑的固定代理端口。保留目标电脑已经安装和运行的 VPN、系统代理和订阅，不改变系统代理、TUN 或防火墙设置。检测到多个可用出口时，需要在工作台选择一次；没有可用出口时不会报告运行条件齐全。

安装会实际执行以下无付费分析检查：

- 使用 CPU 加载随包图像模型并完成一次推理。
- 写入、保存并重新打开含中文、数值和图片的 Excel。
- 启动随包 Chromium 并读取页面内容。
- 使用公司密钥连接 AdsPower，准备 Firefox 内核，创建独立测试环境，激活其窗口并验证 WebDriver、BiDi 和页面内容读取，随后清理这个测试环境。
- 运行工作台 MCP 的真实本地握手，检查公司默认分析密钥已经配置。不会自动发起计费分析请求。

只有基础依赖、当前安装的以上运行检查、公司默认分析配置和工作台 MCP 全部就绪，完整内部部署才报告 `parity_ready=true` 并成功退出。`ready=true` 只代表基础条件，不代表完整部署完成。安装结果保存在 `runtime/install-status.json`，实际运行检查保存在 `runtime/deployment-smoke.json`。API 密钥已配置与该服务余额、实时可用状态分别记录。

部署完成会打开工作台。以后双击 `start-web.cmd`。网页生成并检查品类规则后，再启动采集；第三层分析需在“运行总览”单独点击启动。网站验证码按现有流程处理。

## 后续增量升级

首次部署继续使用完整包。后续提供单独的增量更新包，原完整包和下载链接保留，正在新机部署的同事无需重新下载。

完成当前运行任务后，把增量包解压到单独目录，双击其中的 `update.cmd`，选择原工作台安装目录。程序先校验发行类型、已装版本和文件校验值，备份即将替换的文件，再短暂重启本安装的网页服务。更新失败自动恢复原文件；本机修改过的程序文件会提示冲突，不会直接覆盖。

代码和网页更新只携带变化的文件，保留公司配置、登录授权、采集数据、历史结果、断点以及现有 Python、Node、浏览器和模型。无需重新运行 `deploy.cmd`，也无需重新登录 Codex。使用 Codex Agent 的登录授权仍由各电脑自行管理；普通采集、前两层和第三层 API 分析不需要 Codex 账号。

当前增量机制用于代码及网页更新。依赖锁定版本发生变化时，构建器会拒绝生成缺少依赖迁移的代码补丁，届时另行提供配套依赖更新；不能只覆盖依赖清单后假报升级成功。增量包的 `update-base.json` 可作为下次升级的基准，因此后续升级不需要重新下载完整包。

发布构建使用 `scripts/build_incremental_update.py --base-package <已发布完整包.zip>`；后续可以用 `--base-manifest <上一更新包的update-base.json>`。构建只读取指定 Git 提交的发行源码，不读取本机公司密钥或运行数据。内部更新包发布到私密仓库，公开更新包发布到公共仓库。

安装失败会恢复本次替换前的项目虚拟环境、Node 依赖、便携工具和已导入的公司密钥，保留采集数据、断点和 Excel。旧环境与失败环境保存在 `.deployment-backup/`。错误阶段、脚本行号、异常类型及命令退出码写入脱敏的 `runtime/install-failure.json`，修复原因后可再次运行 `deploy.cmd`。系统级 Python 或 VC++ 安装不会因项目回滚而卸载。

原生安装器的退出码另存于 `runtime/installer-logs/process-*.json`，失败时同时保存在 `install-failure.json` 的 `command` 内。Python 官方安装日志指定到同目录；记录分别标明日志路径及文件是否实际生成。无法取得退出码或非允许退出码都会停止部署，不会把安装器启动成功当成安装完成。这些记录及已有环境上的重试不能代替恢复干净系统后的首装复验。

只读准备检查：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File install.ps1 -PreflightOnly`。外部另行提供的配置仍显示导入确认；管理员明确授权的命令部署可使用 `-AcceptCompanyConfig`。

公司完整包只放在私密仓库或发给获授权同事。公开仓库只同步公开发行源码和公开包，不包含公司配置、运行数据或账号缓存。

## 外部多模态 API 的模型与推理强度


在“运行总览”的第三层设置中选择“DeepSeek / 其他多模态 API”，填写服务地址和对应 Key。程序查询该地址的模型列表，选择模型后按接口返回的能力显示推理档位及默认值。支持 DeepSeek 的 `effort.supported_levels` / `default_level` 元数据，以及兼容服务明确返回的推理枚举。

声明不支持图片的模型会标注且不可选择；没有返回图片能力的接口保留手动配置。接口没有提供推理档位时只使用默认，读取能力不会发送分析请求。选择“默认”会省略强度参数，明确选择档位则传入实际请求。更换模型后恢复默认；保存配置不启动分析，已有结果继续保留。

## 第三层自动发现本机模型

选择“本地部署的模型”后，工作台自动识别本机监听服务，并在后台扫描可访问的本地固定磁盘。常见缓存目录和运行进程指定的模型路径优先；支持识别 Ollama 模型清单、GGUF 权重和带配置及权重的 Hugging Face / Transformers 目录。模型文件不会被导入或执行，不下载新模型，不自动提交分析。

服务发现读取 Ollama、LM Studio 原生模型列表、OpenAI 兼容模型列表及 llama.cpp 的只读能力元数据；支持识别使用非默认端口的本机服务。只有明确声明支持图片的服务模型才进入可连接下拉框。仅发现文件、权重不完整、仅支持文字或能力待确认的模型在扫描结果中单列；不会凭模型名称认定支持看图。需要授权、接口路径特殊、只绑定局域网地址、HTTPS 或未开放模型目录接口的服务可能仍需手动配置，不能承诺发现任意私有部署。

页面显示扫描进度，支持停止和重新扫描。权限受限目录、回收站、系统卷目录、目录链接以及网络和可移动磁盘不在遍历范围；数量过多时明确提示只展示前 2000 处模型。检测的是运行后端程序的电脑，不是仅打开网页的另一台电脑。检测不会更改已选择的分析方案；点击开始第三层后才使用所选模型。服务元数据声明支持看图不代表已经通过实际图像分析或准确性验证。

支持本机 LiquidAI/d1-3B 的原生图片决策服务：服务须通过 `/health` 报告就绪，并提供与 `/v1/decide` 对应的 OpenAPI 图片请求定义。工作台按本机实际监听端口识别，不要求旧电脑的 18181 端口，也不要求此服务提供 Ollama 或 OpenAI 模型列表。选择检测到的“本机 D1 原生图片决策接口”后保存模型选择，再按需要启动第三层；检测和保存不会提交分析。

对已运行在 7863 端口、安装布局和原始脚本符合已支持版本的 D1，`deploy.cmd` 会保全原脚本、更新并发接口，并登记当前 Windows 用户登录后启动的后台服务。该服务使用 D1 自己的 Python、模型和日志目录，不依赖 Codex 或验收控制目录；不下载模型或提交分析。包含其他本机修改的 D1 脚本会保留并提示原因，不直接覆盖。

此接口共享一份模型权重，各请求使用独立并可复用的 CUDA 流；运行并发仍由网页设置。Windows 缺少 FlashAttention 时，按完整因果掩码分块计算，减少临时显存，不裁减商品图片、规则或输入 token。并发数应按实际吞吐选择，多路未必更快；决策确认概率可在网页调整，原始概率保留。

此原生服务每次最多 10 个问题，工作台根据已选图片条件自动减少每批候选数；单对的完整条件仍超过限制时会拒绝发送，保留原有规则。服务的 4096 文本 token 上限由其真实分词器检查，超限会显示服务原因并停止本轮请求，不自动重复推理或删减规则。两侧商品图片和原判定门槛保留；接口连接成功仍须以实际图像响应验证可用范围。

## 已有任务继续与启动记录

点击“开始 / 继续采集”后，网页先显示启动请求已受理；确认监督进程的身份和任务登记后才显示已启动。等待时可以查看状态或点击停止，重复继续会被拒绝。启动失败保留数据和断点，并显示具体错误。

原任务的 `resume_launch.json` 和 `logs/resume_launch.jsonl` 保存这次继续的阶段。Windows 后台启动的 `runtime/web-console/launch-*.json` 与同名 JSONL 记录调度器连接、登记、启动阶段及原生命令结果，便于区分服务仍在运行与监督器尚未启动。运行详情只展示有界诊断摘要；完整商品、分析证据和 Excel 继续从结果页查看。
