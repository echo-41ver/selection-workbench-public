# 换机部署与第三层分析

新任务第三层默认使用 Liquid D1，官方决策接口、模型 d1、初始 4 路并发。D1 Key 在本机使用 Windows 当前用户加密保存；完整内部包携带可迁移配置，新机导入后重新加密。公开包不包含公司密钥。保存配置不会启动付费分析。

原有冻结任务保留服务、模型和进度。API 消费端复用连接池，并在每条请求完成后立即补充下一条，避免慢请求阻塞整轮。D1 自动并发仅使用当前分析中实际完成的数据，从 4 路探索到最多 16 路；吞吐量不再改善或出现失败时退回。手动并发保留。费用未知的请求仍被隔离，不因测速重复发送。

“本地 Agent 多任务分析”检测 Codex CLI、Claude Code、Gemini CLI、OpenCode、WorkBuddy、AccioWork 和豆包。已安装、已登录、实际连接且能读取图片分别显示；未通过看图验证的程序不参与派发。本机 Codex CLI、WorkBuddy、AccioWork、豆包已通过真实随机图片读数测试；Claude、Gemini、OpenCode 未安装，尚未在相应实机完成验收。

本机历史完成记录合计 201 组、2081 对，使用 6 路、每组最多 12 对、同一 Amazon 商品分组。自动调度据此为每个可用 Agent 提供最多 6 路，并受可用内存和总计 24 路限制。这些记录支持该配置可用，未证明它在所有电脑、账户和服务状态下速度最优。

WorkBuddy 使用其随客户端安装的 CodeBuddy CLI 和当前用户登录；AccioWork 使用客户端主动导出的本机任务网关，核对端口进程归属后创建独立任务。豆包使用经用户确认开启的 127.0.0.1 CDP 接口，首次启用需要重启客户端；每次分析创建新聊天并同时发送对照图、原图与完整规则。豆包固定单任务、每组一对，避免多个任务争用输入框。响应不确定时保留原任务并只恢复观察，不自动重新提交。三者均不打包账户登录缓存或本机网关口令；新机需安装并登录对应客户端。

WorkBuddy CLI 在独立后台会话中运行，关闭会话持久保存，因此不会在桌面任务列表里新增任务。工作台将其标为“WorkBuddy（内置 CLI）”。其原生模型列表提供 Fast、Balanced、Primary、Deep 等账号实际可用别名，未披露底层模型名；不能将其宣称为桌面当前选择的 Deepseek-V4.1-Flash。它通过原生 StructuredOutput 工具返回完整字段，父程序校验后才导入结果。三个新增适配器都已用同一对本地商品原图完成独立分析并通过严格校验；验证结果未写入正式采集任务。

本机 Agent 模式先从一个下拉框选择 Agent，再显示其模型下拉框；默认只派发给所选的一个 Agent。额外 Agent 需要在“多 Agent 同时分析”中主动添加，按不同商品分担，每对只分配一次。没有选择 Agent 或模型列表尚未就绪时，网页禁止提交，避免空列表意外派发给全部 Agent。列表来自当前安装程序和当前账号的原生接口：Codex model/list、WorkBuddy/Gemini ACP、Claude 控制初始化、OpenCode models、AccioWork 本机网关和豆包实际模型菜单；不使用固定示例清单。重新识别或换机后重新读取，旧机不可用的模型明确显示失效，文字模型不能参与看图。选定模型传入真实请求，且连接证明按 Agent、模型和当前安装版本分别保存；另一个模型的成功不能替代当前模型验证。本机已安装的四种 Agent 均已通过指定模型的真实随机图片验证；未安装程序的协议测试不等于实机验证。

最终选品 Excel 的可见结论统一为“同款、类似款、不同款、未分析”，保留双方图片、来源链接、数量和一句简短依据。长证据与辅助评分隐藏，已采集完整字段在隐藏表中保留。Agent 支持类似款；身份差异和相似设计须有双边原图事实，证据不足不会强制归为不同款。提示词减少重复要求，不要求模型自行打分；自动补跑仍受现有次数上限、原任务绑定和计费不确定状态隔离约束。

部署资产固定打包本机 Codex CLI 版本及其原生辅助程序。程序优先识别随包工具，再搜索 PATH、官方 Codex 安装目录和常见 npm/用户目录。npm 包装器通过实际 Node 入口调用，路径可包含空格。部署时注册当前安装目录的工作台 MCP，并做真实 stdio 握手；同名条目属于其他安装时使用独立名称，保留原配置。

Codex 使用新机当前用户自己的登录状态。已登录则自动复用并做一次小图片连接测试；未登录时打开官方登录窗口。包中不携带 Codex、Claude、Gemini 的登录缓存。登录完成后在工作台重新检测并连接。D1、Agent 账户额度、网络、AdsPower 登录与网站访问条件属于新机验收的一部分。

部署结果分别报告基础依赖 ready 和完整条件 parity_ready。只有 D1 Key、Codex 实际看图连接、工作台 MCP 和基础依赖都就绪时才报告 parity_ready。当前电脑的隔离验证不能替代第二台干净 Windows 电脑的实际运行验收。

AccioWork 新任务使用桌面来源标记 `from=desktop`，并保存所选原生模型，供客户端桌面任务列表读取。此前缺少该标记的网关会话保留原记录，不重发。豆包聊天输入只携带身份绑定、每项唯一的结构化规格、原图绑定和完整品类规则；原始页面、重复门槛文本及采集元数据保留在本地，不再重复贴入聊天。网页显示“每组最多 12 对”，同一 Amazon 的剩余候选不足时组会更小；豆包仍为每组 1 对、单窗口 1 组。
